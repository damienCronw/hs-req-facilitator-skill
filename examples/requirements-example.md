## 项目概述
本示例展示了如何使用 hs-req-facilitator-skill 分析和改进需求文档。

## 场景：用户管理系统

### 原始需求（模糊）
```
用户管理系统需要能够管理用户。
应该包括用户注册、登录功能。
还需要有用户权限管理。
```

### 改进后（明确）

#### 核心功能需求

**FR-001: 用户注册**
- **用户故事**: 作为新用户，我希望能够注册账号，以便能够使用系统
- **验收标准**:
  - 用户输入有效邮箱和密码（8字符以上，含大小写）
  - 系统验证邮箱唯一性
  - 注册成功后自动发送验证邮件
  - 用户收到验证邮件并点击链接完成验证
  - 验证后账户状态变为"已验证"

**FR-002: 用户登录**
- **用户故事**: 作为已注册用户，我希望能够登录系统，以便访问个人功能
- **验收标准**:
  - 用户输入邮箱/用户名和密码
  - 系统验证凭据正确性
  - 登录成功后创建会话，有效期24小时
  - 支持"记住我"选项，延长至30天
  - 连续5次失败登录锁定账户30分钟

**FR-003: 用户权限管理**
- **用户故事**: 作为管理员，我希望能够管理用户权限，以便控制访问级别
- **验收标准**:
  - 支持角色：普通用户、管理员、超级管理员
  - 管理员可查看所有用户列表
  - 管理员可修改用户角色和状态
  - 超级管理员可删除用户账户
  - 操作需记录审计日志

#### 非功能性需求

**性能需求**
- 页面加载时间 < 2秒
- 用户登录响应时间 < 500ms
- 支持并发用户数：1000

**安全需求**
- 密码使用bcrypt加密存储
- 敏感操作需二次验证
- 会话超时自动登出
- 记录所有登录和权限变更日志

**可用性需求**
- 系统可用性 99.5%
- 维护窗口：每周日凌晨2-4点
- 故障恢复时间 < 4小时

---

## 使用方法

1. 将此文件作为需求文档放入项目根目录
2. 激活 hs-req-facilitator-skill
3. 技能会自动分析并提供改进建议
4. 按照建议完善需求文档
